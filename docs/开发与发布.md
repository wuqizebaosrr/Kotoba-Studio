# 开发与发布

## 环境与命令

目前验证的平台是 Windows x64，开发使用 Node.js 24 和锁定版本的 Electron。首次执行 `npm ci` 会下载依赖。

```sh
npm ci
npm run check
npm run scan:public
npm test
npm run test:desktop
npm start
```

`check` 解析所有代码文件；`test` 检查故事内核、文本、存储、API 模拟与打包逻辑；`test:desktop` 使用独立测试数据运行桌面交互检查，报告和截图保存在 `artifacts/verification`。自检不会使用正式工程库，也不会调用真实收费 API。

编辑器与导出游戏共用 `dist/story-core.js` 和 `dist/stage-player.js`。改动故事状态或渲染时，应同时验证工作台预览与导出后的游戏。`dist` 是源码，不能被通用前端项目的忽略规则排除。

## 生成工作台安装包

```sh
npm run build:windows
```

使用 npm 安装的 Electron 运行环境，并把当前仓库的桌面代码与界面复制到独立的构建目录。输出位于 `releases/`。构建不读取当前用户的制作工程、恢复文件或 API 配置。

单文件启动器由 `desktop/GameLauncher.cs` 编译，依赖 Windows .NET Framework 编译工具。该安装包未配置代码签名；正式分发如需签名，应由维护者使用自己的证书处理，不要提交证书或私钥。

可选环境变量：

| 变量 | 用途 |
| --- | --- |
| `KOTOBA_DATA_DIR` | 正常运行时的用户数据目录 |
| `KOTOBA_ELECTRON_EXE` | 构建时使用的 Electron 可执行文件，默认使用 npm 依赖 |
| `KOTOBA_OUTPUT_DIR` | 工作台安装包输出目录，默认 `releases/` |

## GitHub 工作流

**Windows checks** 在提交或拉取请求后执行语法、公开文件扫描、单元和桌面检查。

**Build Windows** 由维护者在 Actions 中手动运行，构建安装包并上传为工作流 Artifact。检查构建结果后，再将安装包作为 Release 附件发布。工作流只声明仓库内容读取权限，不会自动创建 Release 或修改远程分支。

工作流用法参考 [checkout](https://github.com/actions/checkout)、[setup-node](https://github.com/actions/setup-node)、[upload-artifact](https://github.com/actions/upload-artifact) 官方文档。

## 整理可上传源码

```sh
npm run scan:public
npm run prepare:upload
```

生成的源码 ZIP 位于 `artifacts/`，只包含白名单中的源码、测试、文档和基础预设，不包含 Git 历史、依赖、个人工程或 EXE。文件清单同时输出为 `public-file-manifest.json`。

发布前检查 `git status`，确认没有个人素材、剧情、工程和配置。`.gitignore` 已排除常见运行数据、API 配置、依赖、安装包和私钥扩展名。自动扫描只检查特定标记，不能替代人工确认素材来源和授权。

## 首次上传

1. 在 GitHub 新建仓库，建议命名 `Kotoba-Studio`。
2. 上传本副本中的源码文件和文件夹，保持 `desktop`、`dist`、`docs` 等目录结构。不要上传 `node_modules`、`artifacts` 或 `releases`。
3. `README.md` 会成为仓库首页；使用说明在 `docs/使用说明.md`。
4. 源码 ZIP 若通过浏览器上传到仓库，只会成为一个 ZIP 文件，**不会自动展开成项目**。要发布可浏览源码，应先解压并上传其中的项目内容，或使用 Git 推送。
5. 安装包放在 GitHub Release 的附件中，源码目录中不提交 EXE。
6. 本项目以 MIT 许可证发布，分发源码时保留根目录的 `LICENSE` 和第三方组件许可说明。

如果本地使用 Git，先在 GitHub 建立空仓库，再按该仓库页面提供的 remote 地址推送。不要把访问令牌写进 remote 地址、脚本或仓库配置文件。
